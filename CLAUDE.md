# CLAUDE.md - pibooth

This is a **fork** of [pibooth](https://github.com/pibooth/pibooth) — a Python photo booth application for Raspberry Pi using pygame. The fork is maintained at `github.com/Babacooll/pibooth`.

## Quick Reference

```bash
# Run locally (non-RPi uses mock GPIO)
pibooth ~/.config/pibooth

# Run tests
pytest tests/

# Install in editable mode with DSLR + printer support
pipx install --editable './[dslr,printer]' --include-deps
```

## Architecture

**State machine** drives the UI through these states:

```
wait → choose → chosen → preview → capture → processing → print → finish → wait
                                                                ↘ finish ↗
```

Each state has 4 hook phases: `enter`, `do` (loop), `validate` (returns next state), `exit`.

## Plugin System

Uses **pluggy** for hooks. Two types of plugins:

1. **Core plugins** — classes in `pibooth/plugins/`, registered in `__init__.py`'s `load_all_plugins()`. Called in LIFO order (last registered = first called).
2. **External plugins** — Python modules loaded from file paths via `[GENERAL] plugins` in config, or discovered via setuptools entry points.

### Writing a Core Plugin

```python
import pibooth

class MyPlugin(object):
    name = 'pibooth-core:my-plugin'

    def __init__(self, plugin_manager):
        self._pm = plugin_manager

    @pibooth.hookimpl
    def state_wait_do(self, win):
        # Draw something on win.surface
        pass
```

Register in `__init__.py`:
```python
from pibooth.plugins.my_plugin import MyPlugin
# Add to plugins list in load_all_plugins()
```

### Hook Signatures

Hooks can accept any subset of the defined parameters (pluggy handles this):
- `cfg` — `PiConfigParser` instance
- `app` — `PiApplication` instance
- `win` — `PiWindow` instance (has `.surface`, `.display_size`, `.text_color`)
- `events` — list of pygame events

## Vintone Customizations

### NetworkStatusPlugin

Draws a discreet network indicator pill (top-right corner) showing WiFi/4G/ETH connection type and signal strength bars. Useful for on-site debugging during weddings.

- Located at `pibooth/plugins/network_status_plugin.py`
- Registered as core plugin (drawn last = on top)
- Polls every 5 seconds via `/proc/net/wireless` (WiFi) and `ip route` (interface detection)
- Hidden during `capture` state to avoid visual interference

**Debug override:** Set `PIBOOTH_NET_DEBUG` to force a specific display state without touching the real network:

```bash
PIBOOTH_NET_DEBUG=WiFi:3 pibooth   # 3 green bars, "WiFi" label
PIBOOTH_NET_DEBUG=4G:1 pibooth     # 1 red bar, "4G" label
PIBOOTH_NET_DEBUG=OFF:0 pibooth    # disconnected state
PIBOOTH_NET_DEBUG=ETH:4 pibooth    # full signal, "ETH" label
```

Format: `TYPE:BARS` where BARS is 0-4. Color is automatic (3-4 green, 2 orange, 0-1 red).

### Config Generation

The `pibooth.cfg` file is generated by `vintone-photobooth` (Go CLI) from `pibooth.tmpl`, not edited manually. Theme colors, backgrounds, and print limits come from booking data.

## Display / Window

- `PiWindow.surface` — main pygame surface for all rendering
- `PiWindow.display_size` — tuple `(width, height)` of screen
- Resolution: 1920x1080 fullscreen on RPi
- Main loop runs at 40 FPS (`booth.py:main_loop`)
- `pygame.display.update()` called once per frame after all hooks

## Config Format

INI file at `~/.config/pibooth/pibooth.cfg` with sections:
- `[GENERAL]` — language, directories, plugins, debug mode
- `[WINDOW]` — size, background, font, text color, arrow style, timers
- `[PICTURE]` — captures count, effects, margins, footer text, backgrounds
- `[CAMERA]` — ISO, flip, rotation, resolution
- `[PRINTER]` — printer name, options, max pages, duplicates
- `[CONTROLS]` — GPIO pin assignments, debounce timing
